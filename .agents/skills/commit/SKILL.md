# 커밋 메시지 생성 스킬

## 커밋 컨벤션 기준

형식: `type: description`

| Type       | 설명                           | 예시                                   |
| :--------- | :----------------------------- | :------------------------------------- |
| `feat`     | 새로운 기능 추가               | `feat: 이력서 관리 페이지 개발`        |
| `fix`      | 버그 수정                      | `fix: 로그인 토큰 만료 처리 오류 해결` |
| `docs`     | 문서 수정                      | `docs: README 업데이트`                |
| `style`    | 코드 포맷팅 (로직 변경 없음)   | `style: Lint 수정 및 코드 포맷팅 적용` |
| `refactor` | 코드 리팩토링 (기능 변화 없음) | `refactor: API 호출 로직 개선`         |
| `test`     | 테스트 코드 추가/수정          | `test: 컴포넌트 단위 테스트`           |
| `chore`    | 빌드, 패키지, 환경 설정        | `chore: 라이브러리 버전 업데이트`      |

## 작동 프로세스

1. **작업 범위 식별 (Context Analysis)**
   - 현재 대화 세션(Context Window)의 내역을 꼼꼼히 분석하세요.
   - **이전 커밋 기록이 있는 경우:** 대화 중 이전에 커밋 메시지를 생성한 이력이 있다면, **가장 마지막 커밋 메시지 생성 이후**에 진행된 작업들만 새로운 커밋 대상으로 삼습니다.
   - **이전 커밋 기록이 없는 경우:** 현재 세션에서 진행된 **전체 작업 내용**을 커밋 대상으로 삼습니다.
   - **모노레포 영역 분류:** 식별된 작업 내용을 아래 영역별로 분리합니다:
     - **프런트엔드 (Frontend):** `apps/web` 및 UI/클라이언트 관련 작업
     - **백엔드 (Backend):** `apps/api` 및 서버/데이터베이스/API 관련 작업
     - **공통/루트 (Root/Common, 해당 시):** 프로젝트 루트 설정, 전역 문서, 워크플로우 등 공통 작업
2. **정보 수집 제약 사항 (No Executions)**
   - 변경 사항을 확인하기 위해 `git` 명령어를 터미널에서 실행하거나 파일을 스캔하지 마세요.
   - 오직 **현재 대화 세션의 대화 내역**과 **제공된 컨텍스트**만을 기반으로 변경 사항(수정, 추가, 삭제 등)을 파악해야 합니다.
3. **메시지 작성 규칙**
   - 파악된 작업 내역을 바탕으로, 위의 커밋 컨벤션 기준을 엄격하게 참고하여 가장 적합한 `Type`을 선택하고 명확하게 한국어로 작성합니다.
   - 커밋 메시지는 제목(Title)과 함께 구체적인 변경 사항을 순서가 없는 목록(Unordered List) 형태로 본문(Body)에 포함합니다.
   - **절대로** 파일 경로나 URL을 포함하지 마세요.
   - 커밋 메시지 내에 **볼드체(굵은 글씨)**를 사용하지 마세요.
4. **결과 출력 (Monorepo Output Format)**
   - 사용자가 한 번의 복사로 손쉽게 커밋할 수 있도록, 모든 영역의 변경 사항을 **단 하나의 텍스트 코드 블록**으로 통합하여 제공합니다.
   - **제목 (Title):** 전체 작업을 아우르는 대표 커밋 제목 1줄을 작성합니다. (예: `feat: ...`, `fix: ...` 등)
   - **본문 (Body):** 변경 사항이 발생한 영역에 맞춰 본문 내에서 `[프런트엔드]`, `[백엔드]`, `[공통/루트]` 등의 섹션으로 명확히 구분하고, 각 섹션 하위에 구체적인 변경 사항을 순서가 없는 목록(Unordered List) 형태로 기술합니다.
   - 변경 사항이 없는 영역은 본문에서 생략합니다.
   - **절대로** 파일 경로나 URL을 포함하지 마세요.
   - 커밋 메시지 내에 **볼드체(굵은 글씨)**를 사용하지 마세요.

### 모노레포 출력 형식 예시

```text
feat: 퀘스트 완료 도장 인터랙션 및 상태 동기화 API 연동

[프런트엔드]
- 토벌 퀘스트 완료 시 발자국 도장 인터랙션 구현
- 완료 상태에 따른 취소선 및 애니메이션 효과 적용

[백엔드]
- 퀘스트 상태 변경 API 엔드포인트 구현
- 퀘스트 상태 검증 로직 작성

[공통/루트]
- 프로젝트 공통 환경 설정 업데이트
```
