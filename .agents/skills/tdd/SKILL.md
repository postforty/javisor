# TDD (테스트 주도 개발) 스킬

이 스킬은 요구사항을 테스트 케이스로 먼저 구체화하고, 테스트를 통과하는 최소 코드를 작성한 뒤 리팩터링을 진행하는 **TDD 사이클(Red ➔ Green ➔ Refactor)**을 준수합니다.

---

## 1. 기본 원칙

1. **테스트 우선 (Test-First)**: 실제 기능 코드를 작성하기 전에 반드시 실패하는 테스트 코드를 먼저 작성합니다.
2. **최소 구현 (Minimal Implementation)**: 현재 실패하는 테스트를 통과시키는 데 필요한 가장 단순한 코드만 작성합니다. (오버엔지니어링 금지)
3. **지속적인 리팩터링 (Continuous Refactoring)**: 테스트가 통과된 녹색(Green) 상태에서만 구조 개선, 중복 제거, 가독성 향상 리팩터링을 수행합니다.

---

## 2. 작업 단계 (Red ➔ Green ➔ Refactor)

### Step 1. 요구사항 분석 및 테스트 시나리오 도출
- 사용자의 요구사항을 작은 단위의 기능 명세로 분해합니다.
- 정상 케이스(Happy Path), 경계값 케이스(Edge Case), 예외/오류 케이스(Error Case)를 정리합니다.

### Step 2. 🔴 Red (실패하는 테스트 작성)
- 해당 단위 기능에 대한 테스트 코드를 작성합니다.
- 구현 코드가 없거나 부족하므로 테스트가 실패(Fail)하는 것을 확인합니다.
- 테스트 실패 원인이 의도한 검증 실패인지 확인합니다.

### Step 3. 🟢 Green (테스트 통과 코드 작성)
- 실패한 테스트를 통과시킬 수 있는 최소한의 실제 코드를 작성합니다.
- 복잡한 최적화나 구조 설계를 피하고, 테스트 케이스를 만족하는 데 집중합니다.
- 테스트를 재실행하여 모든 테스트가 통과(Pass)하는지 확인합니다.

### Step 4. 🔵 Refactor (리팩터링)
- 테스트가 모두 통과한 상태에서 코드 품질을 개선합니다:
  - 중복 코드 제거
  - 명확한 네이밍 및 가독성 개선
  - 단일 책임 원칙(SRP) 등 설계 개선
- 리팩터링 후 테스트를 다시 실행하여 기존 기능이 깨지지 않았는지(회귀 테스트) 확인합니다.

---

## 3. 에이전트 지침

1. **단계별 진행 알림**: 작업 시 현재 어떤 단계(🔴 Red / 🟢 Green / 🔵 Refactor)를 진행 중인지 사용자에게 명확히 안내합니다.
2. **테스트 검증 필수**: 가능한 경우 프로젝트 내 테스트 러너(예: `npm test`, `pytest` 등)를 통해 테스트 성공/실패 여부를 직접 검증합니다.
3. **단위 분할**: 한 번에 너무 많은 기능을 개발하지 않고, 작은 단위로 사이클을 여러 번 반복하여 기능을 완성합니다.
